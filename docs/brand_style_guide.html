The Golden Thread

This guide is a chain. What the product is for shapes how it speaks. How it speaks shapes what it looks like. Those choices become components, and the components are built from tokens.

1
Values
Structure you can trust. Someone reading the org chart is making a decision about a person, so the screen has to be right, and it has to be obvious when something cannot be done.
2
Voice
Administrative and exact. A record of a promotion and a refusal to create a reporting loop are written by the same person, in the same register.
3
Visual
Dominant colour: Deep Navy. Barlow Condensed for display, Barlow for body. A 4pt spacing grid. The blue spot colours carry hierarchy depth; the status colours appear only when a record needs attention.
4
Patterns
Node cards, the reporting table, forms, deletion policies, the audit timeline. Every component shows its state, including the states nobody wants: conflict, refusal, empty.
5
Code
--brand-primary
--depth-2 / --sp-4 / --dur-fast

Brand Foundation

From the colour of a blocked reassignment to the wording of a confirmation dialog, everything comes from the same three decisions.

The system holds one organisation's reporting structure and lets an HR administrator read it, search it and change it without ever putting it into a state that cannot exist in real life.

Values

Correctness before convenience. The interface will happily slow a user down to stop them creating a reporting loop, deleting a branch by accident, or overwriting a colleague's edit. Salary is treated as confidential by default, not as an ordinary column that happens to be sensitive.

Voice

The system sounds like a competent administrator explaining what it did and why. It names the people and the fields involved. It does not apologise, soften a refusal, or describe a change in vaguer terms than it has to.

Tone

The stakes change, the voice does not. Renaming a position reads like routine admin. Deleting a manager with 14 reports reads like a decision. Neither one raises its voice.

Every colour, spacing value and duration has a named CSS custom property. Components reference tokens, never raw values, so a change made here propagates everywhere.

Hierarchy depth

Depth tokens alias onto the existing spot colours. The org chart introduces no new hues — it reuses the blue family at descending saturation so that depth reads as a ramp rather than as five unrelated categories. Levels beyond four repeat --depth-4.

Status

Status colour is reserved for the state of a record or an operation. It never indicates seniority, department or headcount — if everything is coloured, nothing is.

Using Tokens in Code

Tokens are defined once in index.css and exposed to Tailwind through the @theme block, so a class and a custom property always resolve to the same value.

Declaring the theme

/* src/index.css — Tailwind v4 */
@import "tailwindcss";

@theme {
  --color-brand-primary: #003a6b;
  --color-brand-mid:     #174585;
  --color-brand-steel:   #6897b8;
  --color-depth-0:       #103364;
  --color-depth-1:       #2042b2;
  --color-depth-2:       #0070bf;
  --color-depth-3:       #0580bb;
  --color-depth-4:       #009193;
  --color-status-safe:     #06b050;
  --color-status-alert:    #ff9300;
  --color-status-critical: #b30000;

  --font-display: "Barlow Condensed", sans-serif;
  --font-sans:    "Barlow", sans-serif;
}

Consuming it in a component

const DEPTH_TOKENS = [
  "border-l-depth-0",
  "border-l-depth-1",
  "border-l-depth-2",
  "border-l-depth-3",
  "border-l-depth-4",
] as const;

export function depthToken(depth: number) {
  return DEPTH_TOKENS[Math.min(depth, DEPTH_TOKENS.length - 1)];
}

<article
  className={cn(
    "w-64 rounded-md border border-l-4 bg-white p-3 shadow-sm",
    depthToken(employee.depth),
    isSelected && "ring-2 ring-brand-primary",
    isInvalidDropTarget && "ring-2 ring-status-critical",
  )}
>
Rule No component may contain a literal hex value, a raw pixel spacing value, or a hardcoded duration. If a value is needed that no token covers, the token set is wrong — add the token, then use it.

Do

Pair every status colour with a word and an icon. A blocked reassignment says why it was blocked and names the employee in the way.

Don't

Use the depth ramp to imply importance, tint whole node cards with status colour, or introduce a colour for "department" — departments are a filter, not a hue.

Motion

Motion exists to show what changed. When a reassignment commits, the chart re-lays out slowly enough that a person can follow where the branch went. Nothing animates on page load. Click a card to play it.

Instant
--dur-instant · 80ms

Hover and press. Fast enough to feel like the control responded, not animated.

Fast
--dur-fast · 150ms

Drop-target highlight during a drag, filter chip removal.

Normal
--dur-normal · 250ms

Expanding or collapsing a branch, opening the employee drawer.

Deliberate
--dur-deliberate · 400ms

Chart re-layout after a reassignment. Slow on purpose: the user needs to see where the branch moved to.

Rule Every transition is wrapped in a prefers-reduced-motion check. With reduced motion on, the chart re-layout becomes an instant jump plus a 1.5s highlight on the moved node — the information is preserved, the movement is not.

Requirements

  • The org chart has a keyboard-navigable nested list equivalent, reachable from the chart toolbar and used as the print layout. It is not a fallback — it is a supported view.
  • Drag-to-reassign has a keyboard path: select an employee, press M, choose a manager from the command palette. Every drag interaction has a non-drag equivalent.
  • Colour never carries meaning alone. Depth is also encoded by position and indentation; drop validity is also encoded by cursor and by a text reason.
  • Blocking errors use role="alert"; confirmations use role="status". A reassignment result is announced, not just drawn.
  • All interactive targets are at least 44 × 44px, including the collapse handle on a node card.
  • Every input has a persistently visible label. Placeholder text is never the only label.
  • Dialogs trap focus, restore it to the trigger on close, and close on Escape. Destructive dialogs open with focus on Cancel.
  • All motion respects prefers-reduced-motion; the chart re-layout degrades to an instant jump plus a highlight.
  • The interface is usable at 200% zoom and down to a 360px viewport.

Voice and Tone

The system is describing changes to real people's records. It says what happened, to whom, and what follows from it.

Write this

"Naledi Phiri now reports to Thandi Mokoena. Her 4 direct reports moved with her."

"Riaan Botha reports to Naledi Phiri indirectly, so he cannot become her manager."

"Deleting Riaan Botha will remove 11 other employees. Review the list before confirming."

Not this

"Employee record successfully updated!"

"Invalid manager selection. Please try again."

"Sorry, this action cannot be completed at this time."

Situation Approach
Something succeeded State the change and its side effects in one sentence. No exclamation marks, no congratulation.
Something is blocked Name the rule, name the people involved, and say what the user can do instead. Never apologise for enforcing a rule.
Something is destructive Give the real count of affected people before the action, and name the action on the button exactly as it was named in the heading.
A screen is empty Say why it is empty and give the one action most likely to fix it.
Something is restricted Say the field is restricted rather than pretending it does not exist. "Restricted", not a blank cell.
Something failed unexpectedly Say what was being attempted and that nothing was changed. Include a reference the user can quote.
Vocabulary An action keeps its name through the whole flow. "Reassign" is the menu item, the dialog heading, the button and the audit entry — it never becomes "move", "change manager" or "update reporting line" along the way.
